What I measured, 12 September 2026: `getLatestPrice()` returned 2427 on mainnet at 08:25 UTC, which reads as US$0.002427 per RBNT once `decimals()` on the feed answered 6. The base fee at that moment was 196,205,387,799,948 wei; times 21,000 gas that is 4.12 RBNT, which is US$0.01 at that price. `eth_gasPrice` was the base fee plus ten percent, and `eth_maxPriorityFeePerGas` was 0. How often the oracle updates is not stated anywhere I read (question 6, partial on cadence). ## What this means for your code

Leave the fee fields alone. wagmi, viem and ethers will read `eth_gasPrice` or the base fee and get it right. If you must set them, use `maxPriorityFeePerGas: 0` with a `maxFeePerGas` at or above the latest base fee. A gas price copied from a config file written last month will be wrong, because it was denominated in RBNT.

Test gas, not fees. `forge snapshot` and gas-used assertions are stable; a fee assertion in wei changes with the RBNT price and, on an anvil fork, does not follow the oracle at all. When you need a number for a human, price it in USD with `gasCostUsd` from `@gatedpath/chains`.

Budget in dollars. A year of operations is gas used times US$0.000000476 per gas unit. No token price forecast is needed, which is the point of the model. The RBNT balance you need to hold does move with the price, so keep a margin; pre-flight will check it.

Show the number yourself. Vine's own warning is that most wallets mishandle gas information on Redbelly. Read the feed and print the USD cost in your interface rather than trusting what the wallet shows.

There is nothing to bid with. With a zero priority fee and an oracle-set base fee there is no fee auction, and therefore no fee-market griefing and no priority-fee games. Gas-limit denial of service inside one transaction still exists.
