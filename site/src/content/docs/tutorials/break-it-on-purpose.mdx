A warm-up, fifteen to thirty minutes, and it changes no code. You are going to try to put this project on mainnet, today, with no preparation, and watch it be refused. Nothing in this project can sign or send anything: there is no wallet in it, and every command only reads. The refusals are worth having seen once while nothing is at stake, because each one is a requirement you will have to meet for real.

I ran the agent track on 12 September 2026 and did the same three attempts by hand on 17 September 2026.

<StepCard n={3} title="Read the refusals as a list of requirements">
<StepPart kind="gets">
What mainnet asks of you, in the tools' own words.
</StepPart>
<StepPart kind="do">
**The deployer must be a verified person.** The script reads the chain id from the RPC, finds the network's permission contract and asks it about the sender before anything else. Foundry's default sender is nobody, so it stops there, before the other checks.

**The admin must be a Safe.** `Admin 0xA2c6… is an externally owned account; on mainnet the admin must be a Safe 1.4.1 with a threshold of at least 2.` No single key holds admin power over something that holds value. [Writing Solidity 5](/solidity/admin-safe-and-timelock/) is the layout.

**The verifier must be real.** `VERIFIER is set (mainnet never deploys a mock verifier)`. The mock that makes testing possible refuses to exist on chain 151.

**The analysis must be fresh.** `No Slither report at reports/slither.json`: the tool wants a static-analysis report newer than your newest source file. I do not have Slither on this machine, so I saw this failure for real.

Notice also what passed: the compiler pins, no secret in the repository's history, and a balance check that priced three million gas at US$1.4286 on both 12 and 17 September, because gas here is priced in dollars.
</StepPart>
<StepPart kind="worked">
You can list the four requirements without looking, and say which tool checks each.
</StepPart>
