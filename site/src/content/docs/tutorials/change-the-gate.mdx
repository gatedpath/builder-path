A warm-up, fifteen to thirty minutes. You start from a fresh project whose token lets in anyone over 18, and you finish with the same token letting in only an AU wholesale investor, with tests that prove the gate moved. It is the smallest change that teaches the most important thing about building here: **the eligibility rule is not code in your contract; it is a number you hand the contract when you deploy it.**

I ran both tracks on a fresh scaffold before writing this page: the agent track on 12 and 14 September 2026, the Solidity track by hand on 17 September 2026. Every count and output below comes from those runs.

<StepCard n={2} title="Understand what you are about to change">
<StepPart kind="gets">
The one idea this project exists to teach, before you touch anything.
</StepPart>
<StepPart kind="do">
Open `contracts/src/GatedERC20.sol` and find the constructor. The token takes a `verifier` and a `requestId` and passes them to `Gated`. Every gated function then asks the verifier one question: is this wallet eligible for this request id. Request id 18 is the over-18 recipe and 708 is the AU wholesale investor recipe; both are written up in the repository's `recipes/` folder and on [Identity for builders](/identity/).

So changing who may use the token does not mean editing the token. It means deploying it with a different number, and proving the number does what you think.
</StepPart>
<StepPart kind="worked">
You can say where the 18 comes from. One search finds it: `grep -rn "REQUEST_ID" contracts/script .env.example` shows the default in `contracts/script/Deploy.s.sol` and the example in `.env.example`.
</StepPart>

<VineAside href="https://vine.redbelly.network/identity/eligibility/" label="Vine: eligibility">
What a credential is, who issues it and how a proof is checked is Redbelly's to explain. What matters for this step is only that your contract never sees the credential, only the verifier's answer.
</VineAside>
</StepCard>

<StepPart kind="worked">
`cd contracts && forge fmt --check` prints nothing, and `npm run test` ends with `72 tests passed, 0 failed` across 8 test suites: the 68 you started with and four new ones. If you directed an agent, its count may differ by a test or two; what must be true is that nothing failed and that a test names request id 708.
</StepPart>
<StepPart kind="ifnot">
A revert that reads `NotEligible(0x…, 18)` in a test you expected to pass means something still deploys with 18; search for it again. The failure table explains [`NotEligible`](/errors/#not-eligible) and its neighbours.
</StepPart>

<StepCard n={4} title="See it on a local copy of testnet">
<StepPart kind="gets">
The contract deployed on your own machine against a fork of testnet, answering for itself which recipe it enforces.
</StepPart>
<StepPart kind="do">
```sh
npm run dev
```

This forks testnet onto a local chain, deploys the token, puts five wallets into the five credential states and starts the web app with its state panel. It holds no key of yours and sends nothing to the real network. In a second terminal, ask the contract directly, with the address the table printed:

```sh
cast call <token-address> 'requestId()(uint64)' --rpc-url http://127.0.0.1:8545
```
</StepPart>
<StepPart kind="worked">
The table's first line ends `request id 708` and the `cast call` prints `708`. In the panel, wallet 3 (Valid) can subscribe; switch it to Revoked and the same button is refused. Ctrl-C stops everything.
</StepPart>
<StepPart kind="ifnot">
[`already running`](/errors/#dev-already-running) means an earlier `npm run dev` is still up; stop it first. If the fork cannot reach the RPC, `npm run dev -- --no-fork` runs on a plain local chain, offline.
</StepPart>
</StepCard>

## What you learned

Recipes are swappable, because the rule is a deploy-time argument and not contract code. Tests are the contract: the change was twelve lines, and the proof was seventy-four. And the local loop shows the gate move before any network sees it. The next project, [Prove the pause](/tutorials/prove-the-pause/), uses the same project folder.
