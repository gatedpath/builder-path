A warm-up, fifteen to thirty minutes, and the first project where the right answer is to write no contract code at all. The token the scaffold gives you already has an emergency pause. What it needs is proof, and writing that proof teaches the two things the card is for: admin power lives behind roles, and an invariant says more than a unit test.

I ran the agent track on 12 September 2026 and did the Solidity track by hand on 17 September 2026. Every count below comes from those runs.

<StepCard n={2} title="Read the pause before you prove it">
<StepPart kind="gets">
The discovery that changes what this project is.
</StepPart>
<StepPart kind="do">
Open `contracts/src/GatedERC20.sol` and find `pause()` and `unpause()`. They are guarded by two different roles: the pauser stops the token and only the admin starts it again. Stopping must never wait and restarting must never be one person's quick decision; [Writing Solidity 5](/solidity/admin-safe-and-timelock/) is about why.

This matters for the card's own wording. Until 18 September 2026 the prompt said "only the admin Safe can flip the pause". That holds when one Safe holds both roles, which is what the deploy script does by default, and not otherwise: the scaffold's own test shows the admin being refused when it tries to pause. The contract kit split the roles after the prompt was written. I reworded it to "only the pauser can pause and only the admin can unpause", and ran it again on a fresh scaffold before this page changed, because a reworded prompt is an unrun prompt.
</StepPart>
<StepPart kind="worked">
You can say who pauses and who unpauses, and why they are not the same.
</StepPart>
</StepCard>

<ProjectPrompt n={2} />

The first version of this prompt said "add an emergency pause". The agent read the contract, found one already there with its role and its events, and declined to add a second; it proved the existing one and strengthened the tests. [Say what you want](/agents-guide/say-what-you-want/) tells that story. A good result touches tests only. If your agent's diff changes anything under `contracts/src/`, ask why.

<StatusPill variant="verified" label="Run 18 Sep 2026, Claude Code, on the reworded prompt" /> The run held the two roles apart: four new tests show the admin refused by `pause()`, the pauser refused by `unpause()`, and both events naming the account that made them, and a new invariant compares everything the token holds against a record taken at the pause, over 2,048 random calls. The suite went from 63 tests to 69, and pre-flight cleared 9 of 9. Two deliberate faults in the contract were each caught. <TabItem label="Writing Solidity">
Add one file, `contracts/test/PauseProof.t.sol`, with three tests. The first expects `Paused(pauser)` and then `Unpaused(admin)`, using `vm.expectEmit`. The second shows a stranger refused on both. The third is the one worth reading closely: take a snapshot at the pause, let everyone try every way of moving a balance, and compare.
