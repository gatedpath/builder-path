# Redbelly Development Tool site

The builder site, an Astro Starlight project. Everything it says about the network traces to
`../RESEARCH.md`; everything it shows as code is extracted from a file the repository compiles
or tests; nothing on it claims a run that did not happen. `design/` is the design study the
site is built from and is not edited here.

Independent builder site for Redbelly Network. Not affiliated with or endorsed by Redbelly
Network Pty Ltd.

## Run it

Node 22, npm. From this folder:

```
npm ci
npm run setup        # once, from a fresh clone: installs and builds the three packages the sample check type-checks
npm run samples      # re-extract code samples from ../packages, ../phase-0, ../report
npm run build        # check:samples, then astro build into dist/
npm run check        # astro check
npm run quality      # build, check, bundle budget, axe, Lighthouse, screenshots
npm run preview      # astro preview of dist/
```

`npm run dev` re-extracts samples and starts the dev server.

## The live status page

`/status` runs no backend and stores nothing. At build, `LiveStatus.astro` reads both governors
RPCs once through `src/lib/status-reader.ts` and renders the figures with the build time, so the
page is complete with JavaScript off and when an RPC is down. In the browser the same reader runs
again from the visitor's own connection (the RPCs answer CORS preflights with `*`, checked 12
September 2026), replaces the figures, labels them "from your browser" with the time, and offers a
"Check again" button; when an RPC does not answer, its card says so and keeps the build-time
figures with their date. Two batched POSTs per chain: five calls (chain id, head, gas price, latest
block, `getLatestPrice()` on the feed) and the last 25 blocks. The page stays inside the 60 KB
client JS budget (34.6 KB gzipped, most of it Starlight's search). Headless Chromium in the build
environment cannot reach external hosts, so the browser path was verified with a mocked RPC in
Playwright and the real endpoints through the build-time read.

## The sample rule

Every code block on a page comes through `<Sample id="…">`, which reads
`src/samples/generated/` and prints where the text came from and what compiles it.
`scripts/check-samples.mjs` runs before every build and fails when:

- a generated extract no longer matches a fresh extraction from its source;
- a published copy under `public/` (llms.txt, the rules files) differs from the package sample;
- `manifest.json` is stale or the generated folder holds an unexpected file;
- an MDX page carries a fenced code block in any language other than shell or plain text
  (commands the reader runs are fences; compiled samples are never fences), or a `<Code>`
  with a literal string;
- a Solidity sample does not compile with solc 0.8.30 for Prague (the site's own solc-js, with
  the sibling files of `solcSources` supplied so relative imports resolve; samples that need
  OpenZeppelin or a rendered template set `solc: false` and name what compiles them instead);
- a TypeScript source's package does not pass `tsc --noEmit` with its own tsconfig (template
  files with placeholders set `typecheck: false` and name the test that compiles the rendered
  result).

Test-file extracts (`test/unit.test.mjs`) are covered by that package's `npm test`, which
the site build does not run; the manifest names the command. The agent-rules samples are
covered by that package's tests, which compare them with the renderer.

Shell blocks are commands, not samples, and the page says when a command has not been
run. On 2026-09-12 the `/start` page was followed literally with Foundry and with Hardhat on
fresh scaffolds against a testnet fork (`../packages/create-redbelly-dapp/reports/golden-path-*.md`);
the commands that have not run are the ones that need a real wallet, and each carries a pill.

## Fonts

Readex Pro (OFL 1.1, reserved name "RevReading Lexend") and JetBrains Mono (OFL 1.1) as the
variable latin subsets Google serves (fetched 12 September 2026; 31,428 and 40,404 bytes),
self-hosted with `font-display: swap`. The sans is preloaded on every page, the mono on the
landing page as well. Nothing loads from a third-party origin at runtime.

## Theme

Starlight's own mechanism: `auto` follows the operating system, and the header toggle
overrides it. `design/tokens.css` sets the dark values on `:root` and the light values under
`:root[data-theme='light']`, the way Starlight's `props.css` is structured. The light theme is
the one that takes after redbelly.network, which is light-only. Code blocks stay navy in both.

## Quality gates

`npm run quality` runs, in order: build, `astro check`, the client JS budget (60 KB gzipped
per page, counting the Pagefind UI chunk Starlight imports on idle), axe on every page at
1440 and 390 in both themes (fails on serious or critical), Lighthouse on `/`, `/start/` and
`/tutorials/` at mobile (default config) and desktop (Lighthouse's desktop preset), failing
under 95 in performance, accessibility or best practices, and screenshots of every page at
1440 and 390 in light plus four pages in dark. Results land in `reports/`. Chromium is the
pre-installed Playwright build at `/opt/pw-browsers/chromium-1194`; override with
`CHROMIUM_PATH`.

## What is honest on the pages

Steps and cards that have not been executed carry a pill saying so: no deploy or Routescan
submission has touched the real network, `forge build` has not been run on the first
contract, and the four recipes are drafts. The golden path has been run on fresh scaffolds
against a testnet fork with both toolchains, and the four warm-up cards have been run with one
agent (Claude Code, 2026-09-12); those cards show the date, the agent and a link to the run
record, and say a second agent is pending. Cards 5 to 12 stay "Verification pending". The
scaffolder, the receptor mock, pre-flight and the MCP server have landed and the pages show
their compiled samples; the ship report generator and the remaining kits have not, and the
pages say so. `/status` is a static shell of the figures in `../report/data/metrics.json`.
